# Linknote

> 日本語版です。正本は [README.md](README.md)（英語）で、内容に食い違いがある場合は英語版が優先します。

**Reading view のまま**、補足を書けます。書いた内容は独立したノートとして保存され、元のノートには小さなマーカーと、Obsidian 標準のブロック ID だけが残ります。

Obsidian 1.6.6 以降が必要です。デスクトップとモバイルの両方で動きます。補足は Reading view から作り、1 件が 1 ファイルなので、Vault を共有する複数の人が同じノートに書き込んでも互いを上書きしません。

要点は、**あなたの書いたものが独立した普通のノートになる**ことです。検索にもグラフにも Bases にも現れます。位置の固定には独自形式ではなく Obsidian の記法を使うので、プラグインを外しても何も壊れません。

**できること**

- Reading view を離れずに補足を書き、独立したノートとして保存します
- Obsidian のブロック参照で位置を固定するので、本文を推敲しても該当箇所に留まります
- 読んでいるノートの補足を、本文の横のカードとして、またサイドバーの一覧として表示します
- どの語句への補足かを示し、本文の該当箇所を指し示します
- 補足とマーカーをまとめて削除します。何が起きるかを事前に明示します
- 何も送信しません。ネットワーク通信は行わず、Vault の外には何も保存しません

## 仕組み

1. Reading view で文字列を選択します。選択のすぐ下に小さなボタンが出ます（モバイルでは画面下部のバーです）
2. **† Linknote** ボタンを押します。**New linknote** という小窓が開きます
3. 補足を書いて保存します

元のノートには、その位置にマーカーとブロック ID が付きます。

```markdown
四半期決算は第10営業日です。 [[Team handbook_k3n8v1|†]] ^k3n8v1
```

補足ノート側は、ノートではなく**そのブロック**を指します。

```markdown
---
source: "[[Team handbook#^k3n8v1]]"
---
```

元のノートに加わるのはこれだけです。マーカーもブロック ID も、Obsidian の普通の記法です。

## なぜ本文に書き込まないのか

多くの注釈プラグインは、コメントを対象ノートの中に置くか、独自の位置形式を持つ別ファイルに置きます。Linknote は逆の道を取ります。元のノートにはアンカーだけを残し、書いた内容のほうを**リンクもタグ付けも検索もできる本物のノート**にします。

位置の固定には Obsidian 自身のブロック参照を使うので、周囲の文章を書き直しても、補足は正しい段落を指し続けます。

## 導入

### Obsidian から

設定 → コミュニティプラグイン → 探す、で **Linknote** を検索し、インストールして有効化します。（申請の判断中です。それまでは下のいずれかを使ってください）

### BRAT から

[BRAT](https://github.com/TfTHacker/obsidian42-brat) を入れ、**Add beta plugin** に `tsuney/obsidian-linknote` と入力します。更新は BRAT が面倒を見ます。**モバイルで現実的なのはこの方法だけ**です。

### 手動で

[最新のリリース](https://github.com/tsuney/obsidian-linknote/releases/latest)から `main.js`・`manifest.json`・`styles.css` を落とし、`<vault>/.obsidian/plugins/linknote/` に置いて、Obsidian を再読み込みして有効化します。

## 補足を書く

**Create linknote from selection** というコマンドが登録されていますので、ホットキーを割り当てれば浮動ボタンを使わずに済みます。ボタンが邪魔なら、設定 → Linknote で消せます。

小窓では `Ctrl/Cmd + Enter` で保存、`Esc` で取り消しです。

本文欄の上にボタンが 2 つあります。**Task** はカーソルのある行を `- [ ] …` に変え、もう一度押すと戻します。**Tag** はタグの入力を始めます（どこでも `#` を打っても同じです）。いずれの場合も Vault にすでにあるタグの一覧が出て、矢印キーで移動、Enter で選べます。この一覧は Obsidian の公開ファイルキャッシュから作っており、非公開 API は使っていません。

## テンプレート

補足ノートは、フロントマターを含めてテンプレートから組み立てます。同梱のものは次のとおりです。

```markdown
---
type: Linknote
created: {{date}} {{time}}
source: "{{sourceBlock}}"
author: {{author}}
selection: {{selectionYaml}}
body: {{bodyYaml}}
---
> [!NOTE]- {{titleShort}}... {{sourceBlock}}
{{selectionQuote}}
## {{bodyHeading}}
{{body}}
```

注釈した箇所は折りたたんだコールアウトに入り、その見出しにはアンカー先へのリンクが付きます。ノートを開いたときに目に入るのは自分が書いた内容で、元の箇所へは 1 クリックで行けます。

**本文見出しは飾りではありません。** 補足ノートの「どこが自分の書いた部分で、どこが引用か」を明示するためのものです。レイアウトから推測するのではなく、明示的な目印を置く設計です。カードはこの見出しの下の節を読み、`body` プロパティもここから書き戻されます。

使える変数は次のとおりです。

| 変数 | 中身 |
| --- | --- |
| `{{title}}` | 小窓で入力したタイトル（省略時は選択文の先頭） |
| `{{titleShort}}` | 同じものを 30 文字で切り、切った場合のみ `…` を付けたもの。見出しやコールアウト向け |
| `{{body}}` | 入力した本文 |
| `{{bodyQuote}}` | 同じもの。各行に `> ` を付けたもの（コールアウトの中に収めるため） |
| `{{bodyYaml}}` | 同じもの。YAML のブロックスカラー形式（プロパティに入れても壊れません） |
| `{{selection}}` | 選択した語句 |
| `{{selectionQuote}}` | 選択した語句。各行に `> ` を付けたもの |
| `{{selectionYaml}}` | 選択した語句。YAML のブロックスカラー形式 |
| `{{source}}` | 元ノートへのリンク |
| `{{sourceName}}` | 元ノートの名前 |
| `{{sourcePath}}` | 元ノートのパス |
| `{{sourceBlock}}` | ノートではなくアンカー先へのリンク。アンカーが無ければノートへのリンクに落ちます |
| `{{embed}}` | アンカーしたブロックの埋め込み。見出しが対象のときは素のリンク。ブロック ID が無ければ空 |
| `{{blockId}}` | ブロック ID（先頭の `^` は含みません）。見出しでは空です |
| `{{anchor}}` | 何に留めたか。ブロック ID、または見出し文 |
| `{{date}}` | 作成日。日付形式は設定に従います |
| `{{time}}` | 作成時刻（`HH:mm`） |
| `{{author}}` | 設定した作成者名 |
| `{{marker}}` | 設定したマーカー文字。端末ごとに変えている場合に有用です |
| `{{bodyHeading}}` | 設定した本文見出し。テンプレートと設定が食い違わなくなります |
| `{{summary}}` | 元ノート名と選択文の抜粋 |

プリセットを 5 つ同梱しています（**Minimal**／**Just a callout**／**With the source embed**／**With the quoted selection**／**Detailed**）。設定 → Linknote → Start from a preset で近いものを選び、書き換えてください。いずれも英語の出発点にすぎません。**プラグインは、あなたが書く言語について何の前提も持ちません。**独自のレイアウトも持たず、あるのは設定したテンプレートだけです。

同じ変数がファイル名テンプレートでも使えます。空の変数が残した区切り記号の連なりは掃除されるため、アンカーが無い場合でも `{{sourceName}}_{{anchor}}` は正しく読めます。完成した名前は 180 バイトで打ち切るので、ラテン文字以外の文字も正しく測られます。

## 補足の付いたノートを読む

マーカーは小さなチップとして描かれ、そのブロックの横には細い縦線が付きます。読んでいる最中に、注釈のある箇所が目に入ります。マーカーにカーソルを合わせると補足の内容が覗けます。

例外が 2 つあります。**見出しには縦線を引きません**（引用の縦棒に見えてしまうためです）。また、見出しのマーカーはファイル上は次の行に置かれますが、読むときは見出しの行に引き上げて描きます。モバイルでは、注釈の付いた箇条書きにも縦線を引きません。モバイルはリストの字下げが浅く、番号と文字の間に線が入ってしまうためです。

いずれも描画時にのみ行うことで、**ノートには余計なものを一切書きません**。*Highlight annotated blocks* をオフにするか、*Marker style* を Plain にすれば、その場で素の見た目に戻ります。ポップアウトしたウィンドウでも動きます。リスナーはウィンドウごとに登録され、小窓はフォーカスのあるウィンドウで開きます。

### サイドバーの一覧

**Show the linknotes in this note**（コマンドパレット、またはリボンのアイコン）で、いま読んでいるノートが持つ補足を、出現順に並べた一覧が開きます。行の見出しはカードと同じ並び（マーカー・作成者・日付）で、その下に補足の対象となった語句、さらに本文が続きます。語句を押すと元ノートのその箇所へ、行を押すと補足ノートが開きます。

行の上には**検索欄と並び順**があります。検索は、入力した各語が行のどこか（作成者・本文・語句・ファイル名）に含まれることを条件とするので、2 語入れると絞られます。入力を正規表現としては解釈しません。並び順は 4 つ（ノート内の順・作成の新しい順・更新の新しい順・作成者順）で、選択は記憶されます。差の付かない行は、ノート内の順序を保ちます。

カードは「ここに何が書かれているか」に答えます。一覧は「このノートについて何がどこに書かれているか」に答えます。モバイルでは一覧が主役です。カードを置く余白が無いためです。

一覧には**範囲**があります。**This note**（このノート）と **Whole vault**（Vault 全体）です。Vault 全体の一覧が**受信箱（Linknote inbox）**で、誰かが書いたすべての補足が既定では更新の新しい順に並び、**Mark all read** ボタンで全件を既読にできます。行の先頭は、この端末がまだ表示していない間は未読の点、既読になるとその補足を書いた人のマーカー文字になります（どちらか一方で、両方は出ません）。このノート範囲の行は一覧に出た時点で既読になりますが、受信箱は行を開いたときにだけ既読にします。

### カード

**Show linknotes as cards** をオンにすると、各補足が対象の箇所の横に描かれます。見出しは、書き込みに使われたマーカー・作成者・日付、その下に対象の語句が 1 行です。アンカーはブロック単位なので、**同じ段落に付いた 2 件はこの語句の行でしか区別できません**（全文はホバーで出ます）。この行を押すと補足ノート全体が開き、ホバーするとファイル名が出ます。マーカーはプロパティではなくノート内のリンクから読むので、実際に使われた文字が出ます。別端末で違う文字を設定していれば、どちらで書いたものかが一目で分かります。

マージンノートには余白が要りますが、Obsidian は余白を残しません（本文列は中央に置かれ、左右に 70〜150px しか残りません）。そこで**カードを持つノートに限り**、本文列を狭めて左へ寄せ、空いた場所にカードを置きます。これがマージンノートの代償で、補足のあるノートにしか適用されません。ペインが狭くて確保できない場合は、対象ブロックの下にカードを置きます（**Card placement** で常時この形にもできます）。**モバイルではカードを一切描きません**（タブレットを含みます）。使える余白が無く、インラインでは読書を妨げるためです。モバイルではマーカーを押すと、画面下からシートが出て、そのブロックの補足が並びます。

同じブロックのカードは 1 本のレールの下にまとめます。上の束を避けるために押し下げられた場合は、細い線が対象ブロックまでの距離を示します。1 ブロックあたり 3 枚、1 枚あたり 6 行が既定で（いずれも設定です）、それ以上はスクロールで読みます。

どれか 1 枚の **–** を押すと、すべてが格納されます。各カードは対象箇所の横の細い帯になるので、どの箇所に補足があるかは分かったまま、本文が場所を取り戻します。帯を押すと戻ります（コマンド **Show or stow the linknote cards** でも同じです）。この状態は記憶されます。

**引用された語句を押すと、カードの横の本文で該当箇所が指し示されます。** ノートには何も書かず、Obsidian の描画結果にも手を加えません。範囲をブラウザのハイライトレジストリに渡し、数秒で自動的に消えます。太字やリンクをまたぐ語句でも正しく塗れるのは、要素で包まないからです。**アンカーはあくまでブロックです。** 記録された語句は「そのブロックのどこか」を示す手がかりに過ぎず、本文が推敲されて語句が無くなっていれば、通知が出るだけで何も起きません。サイドバーの行からも同じことができ、そちらは該当箇所へ移動してから光ります。

対象の語句は補足ノートの `selection` プロパティから読みます。それを持たない古い補足では、同梱テンプレートが語句を収めている引用から拾います。**元ノートからの推測は一切しません。** 表示されるのは、補足を作った時点で記録された内容です。

カードに出る本文は、**本文見出し**（既定は `Linknote`）の下の節です。補足ノートを編集すると、元のノートを開き直さなくてもカードが追随します。その見出しを持たない補足では `body` プロパティ、それも無ければノート全体に落ちます。

### 補足を削除する

カード、サイドバーの行、シートの **×** を押します。まず何が起きるかを明示する窓が出ます。補足ノートは Vault の削除先へ送られ、元ノートからマーカーが取り除かれ、ブロック ID も一緒に消えます。ただし **Vault の他の場所がそのブロックを参照している場合は、ID を残してマーカーだけを取り除きます**。どちらのノートも、それ以外は一切触りません。

2 つの場合には、当てずっぽうで進めずに中止します。元ノートが同じ補足へ複数の場所からリンクしている場合、どのマーカーを外すべきか決められません。また、確認の窓を開いている間に元ノートが変更された場合は、あなたの編集を上書きしないために削除を取りやめます。

## 補足を活用する

補足は普通のノートです。それこそが要点で、このプラグインの助けなしに検索・グラフ・バックリンクに現れます。加えて 2 つのプロパティが役に立ちます。

- `source` は注釈した**ブロック**を指すので、辿ると長いノートの先頭ではなく該当箇所に着きます
- `body` は書いた内容を素のテキストで持つので、クエリでファイル全体ではなく注釈そのものを絞り込んで表示できます

同梱テンプレートを使っていれば、`Linknotes` フォルダに対する Bases のビューで `source`・`author`・`body` を並べるだけで、自分が書いたすべての注釈が 1 つの表になります。カードが読むのも同じプロパティですから、**クエリで見られるものは本文の横にも置ける**ということです。

**ノートが原本で、プロパティはその写しです。** プロパティを直接編集しても残りません。次に Linknote がそのファイルを読んだときにノートから上書きされます。内容を変えたいときはノートを変えてください。*Write the body property from the note* をオフにすると、写しも上書きも止まります。

## 複数人で 1 つのノートに

人と共有した Vault（Obsidian Sync は有償ですが、補足はただの Markdown なので、どのファイル同期でも構いません）では、複数の読み手が 1 つのノートに注釈を付けられます。**補足は 1 件が 1 ファイル**なので、2 人が同時に書いても互いを上書きしません。1 つのノートに複数の作成者の注釈が溜まり、それぞれが作られた箇所に留まり、本文の推敲後もその箇所を指し続けます。

端末ごとに **Author** を設定し、人ごとに違う **Marker character** を割り当ててください。カードとサイドバーの行の見出しが「マーカー・作成者・日付」になるので、誰が何を書いたかが一目で分かります。**Linknote folder は全員が同じにしてください。** 他人の文字で書かれたマーカーを認識できるのは、この設定によります。打ち合わせでは、Reading view のまま画面を共有し、話に出たそばから補足を書けます。

他の人の補足は、向こうから知らせてきます。同期で届いたとき、また起動時には Vault を閉じていた間に届いた分がまとめて、作成者ごとに集計された 1 本の通知になります（例：*3 linknotes updated (Yamada: 2 new · Sato: 1 edited)*）。通知を押すと受信箱が開きます。通知は待ってくれないので、**リボンのアイコンには未読件数**が出ます。こちらは読むまで消えません。自分の **Author** 設定と作成者が一致する補足は通知されません。既読の記録は端末ごとにアプリのローカルストレージへ保存され、同期には載りません。この端末が何を表示したかの記憶だからです。通知は設定でオフにできます。オフにしても点は残ります。

**Linknote は競合について何もしません。** 2 人が同時に同じ元ノートを編集した場合の扱いは、同期ツールに委ねます。オフラインで同じブロックに書かれた 2 件が、同じファイル名を要求することもあります。**Author は身元ではなく設定**であり、既定は空欄です（空欄なら行には日付だけが出ます）。カードはデスクトップの Reading view のみですので、画面共有では発表者にしか見えません。他の人は、次の同期で補足を目にします。

| Marker character | `†` | アンカーした位置に残す文字 |
| Add a block ID | オン | `{{embed}}` に必要です |
| Add a link marker | オン | カード・一覧・削除が補足を見つける手がかり。オフにするとブロック ID だけが残ります |
| Marker style | Chip | チップ表示か、素のリンクか |
| Highlight annotated blocks | オン | 補足を持つブロックの横の細い縦線 |
| Show linknotes as cards | オフ | 各補足を対象箇所の横に描きます |
| Card width | 240px | マージンに確保する幅が連動します |
| Lines shown per card | 6 | スクロールに入るまでに見せる行数 |
| Cards shown per block | 3 | 超えた分は束のスクロールで。0 で全部 |
| Card text size | 100 | Obsidian の小さめの UI 文字に対する百分率（70〜200） |
| Card text color | Normal | Normal・Muted・Faint・Accent はテーマに従います。Custom は従いません |
| Custom card text color | — | Card text color が Custom のときだけ出ます |
| Start with cards stowed | オフ | 格納したカードは対象箇所の横の細い帯です |
| Card placement | In the margin | ペインが狭ければどちらでもインラインになります。モバイルではカードを描きません |
| Body heading | `Linknote` | 補足ノートの中で、自分の書いた部分を示す見出し |
| Keep the body property in step with the note | オン | ノートが勝ちます。プロパティへの編集は上書きされます |
| Show the Linknote button when text is selected | オン | ホットキーだけで使うならオフに |
| Open the linknote after creating it | オフ | ブロック参照が解決してから分割ビューで開きます |
| Notify when linknotes change | オン | 他の人の追加・編集をまとめて 1 本の通知にします。オフでも未読の点は残ります |

## 位置の固定の仕組み

Reading view は Markdown を描画したものですから、難しいのは**描画された選択範囲を元ファイルの位置に戻す**ことです。Linknote は、ノートが描かれる際に「描画要素とその描画コンテキスト」の対応を記録しておき、選択された瞬間にそのコンテキストへブロックの元ソース範囲を尋ねます（公開 API の `MarkdownPostProcessorContext.getSectionInfo()`）。

書き戻しに行番号は使いません。ブロックの元テキストを現在のファイルと照合して位置を決めます。Reading view が返すのは描画後のテキストで、ファイルにはまだ記法が残っているため、両側の記法を正規化してから比べます。**ブロックが見つからない場合、あるいは同じテキストが複数ある場合は、当てずっぽうで書かずに中止します。**

アンカーはブロック単位で、Obsidian 自身のブロック参照に合わせています。表・コードブロック・数式ブロックは、行末に足すと記法が壊れるため、直後の行にアンカーを置きます。箇条書きの中では、リスト全体ではなく選択された項目に付きます。

マーカー文字は設定であり、端末ごとに違って構いません。そのため、マーカーは 2 通りで認識します。**この端末の文字で書かれているか**、または**この端末が設定している補足フォルダ宛の短いリンク（4 文字以下、空白なし）であるか**です。フォルダが未設定なら文字だけで判断します。後者の規則があるおかげで、スマートフォンで書いた補足がデスクトップでもカードになります。フォルダ宛でも長いリンクは、普通の文章として扱い、手を触れません。

見出しは特別扱いです。Obsidian には見出し用のブロック ID がなく、見出し行に何かを足せばその文字列が変わり、そこを指す `[[Note#Heading]]` がすべて壊れます。そこでマーカーは次の行に置き、Reading view では見出しの隣に引き上げて描きます。同じ理由で、アンカーが見出しのときは `{{embed}}` が素のリンクになります。`![[Note#Heading]]` は節全体を取り込むため、最上位の見出しではノートの大半になってしまうからです。

## 既知の制約

- Reading view のみです。Live Preview はもともと編集できるので、解くべき問題がありません
- アンカーはブロック単位です。長い段落の中の一文を選んでも、段落に付きます。正確な語句を残したい場合はテンプレートに `{{selection}}` を入れてください
- コールアウトや引用の中では、コールアウト全体ではなくその行に付きます
- 見出しはブロック ID ではなく見出しアンカーで参照します。あとで見出しを改名すると参照が切れます（ブロック ID は編集に耐えます）
- ノート内に完全に同じ文面のブロックが 2 つある場合、あるいは同じ文面のリスト項目が 2 つある場合、どちらかを選ばずに中止します
- カードは Reading view のみ、モバイル（タブレットを含む）では描きません。そちらではサイドバー一覧と、マーカーで開くシートが役割を担います
- 1 つのビューで 1 件の補足につきカードは 1 枚です。同じノートの別々のブロックに同じ補足が付いている場合、カードが出るのは最初の 1 か所だけです
- 本文の語句を指し示すにはブラウザのハイライトレジストリが必要です。無い環境では、語句を押しても何も起きません
- 長いノートは全体が描画されているわけではないため、遠くの語句は一度そこへ移動しないと指し示せません。サイドバーからはその移動が入ります。プラグインは約 3 秒待ち、駄目なら黙って諦めます（違う箇所を光らせないためです）
- タグの一覧は、最初に必要になった時点で Vault のファイルキャッシュを辿って作ります
- 削除は当てずっぽうで進めません。元ノートが同じ補足へ複数の場所からリンクしている場合、または確認中に元ノートが変更された場合は、何も削除せずに理由を伝えます

## 開発に参加する

Issue と Pull Request を歓迎します。ビルド手順のない素の JavaScript です。`main.js` を編集して Obsidian を再読み込みするだけです。

テストは依存なしの Node で動きます。

```bash
node test.js              # 純関数：アンカー付与、日付、テンプレート、タグ
node test/integration.js  # 偽の Vault に対する補足ノート生成の通し
```
